Overview

This site is the studio’s home: case studies, the websites and products I have built, a shop of Canva media kits, Kreeator Academy and a newsletter. It started as a Framer site and I rebuilt it by hand as a plain static site with no build step and no subscription.

Every page you are reading, including this one, is part of the project.

The problem

A portfolio built on a template looks like every other portfolio and costs a subscription forever. I needed a site I fully own, that loads fast, that I can change in a text editor, and that carries the shop and the course platform without a second tool.

Who it’s for

Hiring managers and clients reading a case study on a phone between two meetings, who need the point in the first screen.

Shop and Academy customers, who need checkout and login to just work.

Me, as the maintainer: adding a case study has to be copying a folder, not learning a tool.

Constraints

Keep the exact look of the Framer original (every token, shadow and animation preset) while removing the dependency.

Keep the old URLs working so nothing breaks for people who already have a link.

No build step and no framework, so everything is hand-written HTML, CSS and a little JavaScript.

Self-hosted fonts and images, screenshots refreshed automatically by a GitHub Action so the website cards never go stale.

Process

Research

I read the Framer site’s rendered CSS value by value and wrote them down as design tokens and breakpoints before writing a line of the rebuild, so the result would match 1:1. Then I audited every page for what was template and what was mine.

Structure

Home, case studies in two families (brand identity, websites and products), Pricing, Shop, Academy, About, newsletter, 404. The case-study template is one HTML pattern reused by every project.

WHY THIS DECISION

Plain static files instead of a framework, because the site needs to live for years with no maintenance and no monthly bill, and a text editor is all it should take.

WHY THIS DECISION

Screenshots taken by a script on a schedule rather than by hand, because the website cards go stale the moment a site changes, and stale screenshots look like neglect.

WHY THIS DECISION

Dark case studies on a light home page, so the home stays airy and the work gets a cinematic frame.

What I designed and built

01 - The home page

Hero, product work, websites, brand identity, about and experience, with the appear animations, pixel canvases and meteors re-created from the original in a few hundred lines of JavaScript.

02 - The case-study template

Overview, problem, users, constraints, process with decisions, what I built, deliverables and outcome. The same pattern for every project.

03 - Shop and Academy

Canva media kits sold through Stripe, and a course platform with accounts, lessons and certificates on Supabase.

04 - The tooling

A screenshot script on GitHub Actions, redirects for the old URLs, a sitemap and social previews for every page.
